# گزارش ممیزی مستقل `pyquaidsce` نسخهٔ 1.0.1

تاریخ ممیزی: 2026-08-02

## ارزیابی نهایی

**وضعیت: قابل استفاده برای بازتولید `quaidsce_c` با `method(ifgnls)`، با
ملاحظات روش‌شناختی صریح زیر.** هستهٔ معادلات، قیود، پروبیت مرحلهٔ اول،
تابع درست‌نمایی، کوواریانس GNR و سه بلوک کشش در benchmark چهارکالایی با

نسخهٔ 1.0.1 تعمیر شد.

## ممیزی نظری

پیاده‌سازی با مشخصات QUAIDS در Poi (2012) سازگار است:

- شاخص قیمت translog، تجمیع‌کنندهٔ Cobb-Douglas یعنی `b(p)`، مقیاس جمعیتی
  Ray یعنی `m0(z)=1+rho'z` و `c(p,z)` درست پیاده شده‌اند.
- تقارن و همگنی `gamma` و قید جمع‌پذیری `eta` از طریق پارامتردهی اعمال
  می‌شوند. در حالت بدون سانسور، adding-up برای `alpha`، `beta` و `lambda`
  نیز اعمال و معادلهٔ آخر حذف می‌شود.
- با سانسور، تبدیل Shonkwiler-Yen به‌صورت
  `Phi_i*w_i* + delta_i*phi_i` و همهٔ معادلات مشترکاً تخمین زده می‌شوند؛
  این همان رفتار سورس Stata است.
- کشش درآمدی، کشش مارشالی و کشش هیکسی با فرمول Poi و اتحاد Slutsky
  تطبیق دارند. در نقطهٔ سازگار با مدل، آزمون‌های Engel aggregation،
  Cournot/homogeneity و compensated homogeneity در حد خطای ممیز شناور صفرند.

### نکتهٔ نظری بسیار مهم

سورس Stata بعد از `probit` دستور `predict` را بدون `xb` اجرا می‌کند. خروجی
پیش‌فرض احتمال است؛ سپس دوباره `normal()` و `normalden()` روی آن اعمال
می‌شود. بنابراین Stata عملاً از `Phi(Phi(x'tau))` و `phi(Phi(x'tau))`
استفاده می‌کند، نه فرمول مقاله یعنی `Phi(x'tau)` و `phi(x'tau)`.

- برای بازتولید مقاله/نتایج Stata: `first_stage_predict="pr"`.
- برای تخمین‌گر نظری Shonkwiler-Yen: `first_stage_predict="xb"`.

این صرفاً تفاوت عددی کوچک نیست؛ در benchmark بزرگ ثبت‌شده در بسته، تغییر
آن log-likelihood را حدود 20 درصد جابه‌جا کرده است. برای مقاله بهتر است هر دو
به‌عنوان تحلیل حساسیت گزارش شوند.

## ایرادهای بستهٔ اولیهٔ Python و تعمیرها

1. **شدت زیاد — bootstrap تنظیم الگوریتم کاربر را منتقل نمی‌کرد.** اگر
   تخمین اصلی با GN اجرا می‌شد، replicateها بی‌صدا با پیش‌فرض LM اجرا
   می‌شدند. اکنون `algorithm`، قواعد توقف و همهٔ حدود تکرار منتقل می‌شوند.
2. **شدت زیاد — replicate نامتقارب موفق شمرده می‌شد.** اکنون replicate
   نامتقارب حذف و گزارش می‌شود و برای محاسبهٔ SE دست‌کم دو اجرای موفق لازم است.
3. **شدت زیاد — پرچم همگرایی IFGNLS می‌توانست کاذب باشد.** رسیدن به
   `max_outer` بدون رسیدن به نقطهٔ ثابت اکنون `converged=False` می‌دهد؛ شکست
   line search نیز دیگر خودکار همگرایی تلقی نمی‌شود.
4. **شدت متوسط — API عمومی LM را پیش‌فرض می‌گرفت، ولی benchmark و README
   بر GN متکی بودند.** پیش‌فرض اکنون GN است. LM همچنان گزینه‌ای صریح است.
5. **شدت متوسط — bootstrap همیشه warm-start بود.** شروع صفر اکنون پیش‌فرض
   وفادار است؛ `bootstrap_start="warm"` گزینهٔ سریع‌تر ولی مستعد اپتیمم محلی است.
6. **شدت متوسط — اجرای موازی فقط روی سیستم‌های دارای `fork` کار می‌کرد.**
   fallback به `spawn` برای Windows اضافه شد و ترتیب replicateها قطعی شد.
7. **شدت متوسط — ابزارهای benchmark مسیر `bench/` را اشتباه می‌ساختند.**
   مسیرها نسبت به ریشهٔ پروژه اصلاح و مسیر ریپوی Stata قابل تنظیم شد.
8. **شدت متوسط — فایل‌های موسوم به test توسط test runner جمع‌آوری نمی‌شدند.**
   مجموعهٔ `unittest` واقعی با هفت آزمون، شامل regression انتهابه‌انتهای Stata،
   اضافه شد.
9. **شدت کم — توضیح شاخهٔ `noquadratic+demographics+censor` متناقض بود.**
   Stata خطا نمی‌دهد؛ کشش درآمدی نهفته را بی‌صدا صفر می‌گیرد. متن و notes اصلاح شد.
10. **شدت کم — `summary(elasticities=False)` در مسیر `nocensor` می‌توانست
    ضرایب معتبر را حذف کند.** اصلاح شد.
11. اعتبارسنجی ورودی برای switchها، طول `initial`، شکل `sigma_initial`،
    سهم منفی، نبود مشاهدهٔ کامل و نبود تغییرات در متغیر مشارکت اضافه شد.

## `initial` در Python و Stata

در Python، `initial=` فعال و آزموده است. بردار باید دقیقاً طول
`res.spec.n_free` داشته باشد و ترتیب آن همان `res.theta` است:

```python
res2 = quaidsce(..., method="ifgnls", initial=res.theta)
```

در سورس Stata v2.0، بررسی طول `initial()` در حالت سانسورشده از تعداد
پارامترهای کوچک‌ترِ بدون سانسور (`np`) استفاده می‌کند، ولی سپس همان بردار را
به `nlsur` با تعداد بزرگ‌تر (`np2`) می‌دهد. بنابراین مسیر censored `initial()`
در ado ناسازگار است. کارکرد صحیح Python یک تعمیر آگاهانه است.

## تفسیر لاگ‌های قدیمی کشش

فایل‌های `log/censor_*_elast_*.log` با `quaidsce_estat.ado` قدیمی ساخته شده‌اند؛
این فایل دیگر در نسخهٔ 2.0 وجود ندارد. بعضی مقادیر آن لاگ‌ها با اتحاد Slutsky
نسخهٔ فعلی سازگار نیستند. این موضوع صحت benchmark فعلی را زیر سؤال نمی‌برد؛
فقط یعنی آن لاگ‌های قدیمی مرجع معتبر برای مقایسهٔ کشش‌های v2.0 نیستند.
مرجع مناسب همین `small4.log` است که هر سه بلوک کشش را از کد فعلی چاپ می‌کند.

## ملاحظات ضروری برای استفاده در مقاله

- برای تطبیق با Stata از این تنظیم‌ها استفاده شود:
  `method="ifgnls"`, `algorithm="gn"`, `start="zero"`,
  `first_stage_predict="pr"`, `strict_stata=True`.
- خطاهای استاندارد مرحلهٔ دوم بدون bootstrap، عدم‌قطعیت متغیرهای تولیدشدهٔ
  مرحلهٔ اول را پوشش نمی‌دهند. برای استنباط مقاله از bootstrap استفاده شود.
- seed یکسان در Python و Stata نمونه‌های bootstrap یکسان نمی‌سازد. برای
  مقایسهٔ replicate‌به‌replicate باید اندیس‌های resample مشترک از بیرون تهیه شود.
- `bootstrap_start="zero"` وفادارتر است. حالت `"warm"` سریع‌تر است ولی در
  معیار دارای اپتیمم محلی می‌تواند توزیع bootstrap را عوض کند.
- زمان 10 دقیقه برای مسئلهٔ 11 کالا/37 هزار مشاهده یک اندازه‌گیری تاریخی روی
  سخت‌افزار مشخص است، نه تضمین. زمان واقعی تابع CPU/BLAS، تعداد تکرارهای
  IFGNLS و به‌ویژه تعداد bootstrap است.
- benchmark بزرگ 17کالایی موجود در اسناد بسته در این ممیزی طولانی دوباره
  انتهابه‌انتها اجرا نشد؛ کنترل قطعی این ممیزی، benchmark چهارکالاییِ مشتق‌شده
  از همان دیتاست و لاگ 17رقمی کاربر است.
